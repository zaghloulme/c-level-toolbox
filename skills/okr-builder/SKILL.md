# OKR Builder

## Core Principle

OKRs ARE NOT A TO-DO LIST — THEY ARE ASPIRATIONAL OBJECTIVES WITH MEASURABLE OUTCOMES. IF YOU HIT 100% OF YOUR OKRs, YOU SET THEM TOO LOW.

## Phase 1: Context

### Required Inputs

| Input | What to Ask | Default |
|-------|------------|---------|
| **Time period** | "Are these OKRs for a quarter or a year?" | Quarterly |
| **Organization level** | "Are these company-wide, division-level, or team-level OKRs?" | Company-wide |
| **Top priority** | "What is the single most important thing the organization needs to achieve this period?" | No default |
| **Team size** | "How many people will work toward these OKRs?" | No default — must be provided |
| **Previous OKRs** | "Have you used OKRs before? Any from the last period to review?" | First time |

**GATE: Confirm context before writing OKRs.**

## Phase 2: Write OKRs

### OKR Rules

- **2-4 objectives per period** — fewer is better; focus over coverage
- **2-4 key results per objective** — each must be measurable
- **Objectives are qualitative** — inspiring, directional, memorable
- **Key results are quantitative** — specific numbers, dates, or binary milestones
- **70% achievement = success** — OKRs should be stretch goals, not guaranteed targets

### OKR Template

```
## Q[X] [Year] OKRs — [Organization/Division Name]

### Objective 1: [Inspiring, qualitative statement]

| # | Key Result | Starting Point | Target | Current | Score |
|---|-----------|---------------|--------|---------|-------|
| 1.1 | [Measurable outcome] | [Baseline] | [Target] | — | — |
| 1.2 | [Measurable outcome] | [Baseline] | [Target] | — | — |
| 1.3 | [Measurable outcome] | [Baseline] | [Target] | — | — |

### Objective 2: [Inspiring, qualitative statement]

| # | Key Result | Starting Point | Target | Current | Score |
|---|-----------|---------------|--------|---------|-------|
| 2.1 | [Measurable outcome] | [Baseline] | [Target] | — | — |
| 2.2 | [Measurable outcome] | [Baseline] | [Target] | — | — |
```

### Good vs. Bad OKRs

**Good Objective:** "Become the most reliable delivery partner in the mid-market segment"
**Bad Objective:** "Improve customer service" (too vague, not inspiring)

**Good Key Result:** "Reduce average delivery time from 14 days to 9 days by end of Q3"
**Bad Key Result:** "Work on delivery speed" (not measurable)

**Good Key Result:** "Achieve NPS of 58+ across all enterprise accounts (currently 44)"
**Bad Key Result:** "Improve NPS" (no baseline, no target)

**GATE: Present OKRs for review and refinement before adding scoring.**

## Phase 3: Scoring System

### Scoring Rubric

```
## OKR Scoring Guide

| Score | Meaning | Description |
|-------|---------|-------------|
| 0.0 | No progress | Key result not started or abandoned |
| 0.3 | Some progress | Meaningful effort but significantly short of target |
| 0.5 | Halfway | Solid progress, roughly half the target achieved |
| 0.7 | Target zone | Strong performance — the expected zone for stretch goals |
| 1.0 | Full achievement | Hit or exceeded the target — may indicate target was too easy |
```

### Check-In Cadence

```
## OKR Check-In Schedule

Weekly (5 min): Update current numbers for each key result
Mid-period (30 min): Score all OKRs at midpoint. Identify anything tracking at 0.0-0.3 and define interventions
End of period (1 hour): Final scoring, reflection, and input for next period's OKRs
```

## Phase 4: Review and Iterate

### Quarterly Review Template

```
## Q[X] OKR Review

**Overall score:** [Average across all key results]

### Objective 1: [Name] — Score: [X.X]
- KR 1.1: [Score] — [What happened and why]
- KR 1.2: [Score] — [What happened and why]

**What drove progress:**
**What blocked progress:**
**Carry forward to next quarter?** [Yes/No — if yes, adjust the targets]

### Lessons Learned
- [Lesson about OKR setting]
- [Lesson about execution]
```

### OKR Retrospective Questions

1. Were our objectives the right priorities for this period?
2. Were key results within our control, or did they depend on external factors?
3. Did we check in frequently enough?
4. What scored below 0.3 and what was the root cause?
5. What would we set differently next period?

## Anti-Patterns

- **Key results that are tasks** — "Launch new reporting system" is a task. "Finance team closes month-end 5 days faster by Q3" is a key result.
- **Too many OKRs** — more than 4 objectives per period dilutes focus. If everything is a priority, nothing is.
- **Setting conservative targets to guarantee 1.0** — this defeats the purpose. OKRs should make the team uncomfortable.
- **No baseline measurement** — you cannot track progress without knowing where you started.
- **Setting and forgetting** — OKRs without weekly check-ins become forgotten documents within three weeks.

## Recovery

- **Team conflates OKRs with tasks:** Clarify the hierarchy — OKRs set direction, projects are the vehicles, tasks are the steps. OKRs answer "what does success look like," not "what will we do."
- **All key results score 1.0:** Targets were too conservative. Next period, set targets that feel 30% beyond comfortable.
- **All key results score below 0.3:** Either the objectives were wrong, the time horizon was too short, or resources were insufficient. Diagnose the specific cause before re-setting.
- **Only one objective:** Fine. Set 3-4 strong key results for that single objective.
- **Request to change OKRs mid-period:** Resist unless the business context has fundamentally changed (market shift, acquisition, major restructuring). Changing OKRs mid-cycle trains the organization to abandon goals when they get difficult.
